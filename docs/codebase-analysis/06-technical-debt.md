### C-1. 공동 공과금이 항상 0원으로 저장된다 (FE/BE 계약 파손)

| | |
|---|---|
| **문제** | 계산기의 공동 공과금 폼이 보내는 필드와 백엔드가 읽는 필드가 완전히 어긋나 있다. 총액이 항상 0으로 저장되면서 **"저장되었습니다" 성공 메시지가 표시된다.** |

| **회귀 시점** | `ef3a627`(분배방식) → `e4542c7`(총액/설명). **두 커밋 모두 메시지가 "계산기 페이지 UI 폴리싱"** |
| **개선 방향** | ① FE/BE 필드 계약을 하나의 스키마로 정의(Pydantic/dataclass) ② 3개 항목 입력을 유지할지 단일 총액으로 되돌릴지 제품 결정 필요 ③ **회귀 테스트 필수** — 이 버그는 테스트 1개로 막을 수 있었다 |

### C-8. 전기요금 덮어쓰기가 절대 동작하지 않는다

| | |
|---|---|
| **문제** | 동일 (층, 정산월)에 대해 **재계산이 불가능**하다 |
| **위치** | `templates/calculator.html:113, 906` ↔ `app.py:757-758` |
| **상세** | ① 체크박스에 `value` 속성이 없어 `"on"` 이 전송되는데 BE는 `== 'true'` 를 기대 ② FE 재시도 분기가 `j.already_exists` 를 보는데 BE는 `exists` 를 반환 → **두 경로 모두 죽어 있다** |
| **왜 문제인가** | 검침값이나 금액을 잘못 입력하면 조회 페이지에서 수동 삭제 후 처음부터 재입력해야 한다. 그런데 그 계산이 이미 정산서에 포함되어 있으면 **삭제도 FK 제약으로 실패**한다(F-13) → **막다른 골목** |
| **비교** | 수도 탭은 FE가 `fd.set('overwrite', ...)` 로 명시 변환하므로 **정상 동작**한다(`calculator.html:929`). 전기 탭만 누락 |
| **영향 범위** | 전기요금 계산 워크플로 |
| **개선 방향** | ① 응답 키 이름 통일(`exists` ↔ `already_exists`) ② 불리언 파라미터 파싱을 공용 헬퍼로 (`'on'/'true'/'1'/'yes'` 허용) ③ 재계산 시 정산서 참조 여부를 먼저 확인해 사용자에게 명확히 안내 |
