## 결론

v1.0.5는 이번 달 정산서만 완납하려고 했는데 별도로 남아 있던 과거 미납까지 입금액에 자동 합산되어 해당 정산서가 초과입금으로 표시되던 문제를 수정했다.

- `이번 정산서 잔액 입력`은 선택한 정산서의 남은 금액만 입력한다.
- 이월 미납이 정산서에 실제 포함돼 있다면 이월 포함 정산서 금액을 기준으로 완납 처리한다.
- 이번 정산서 잔액과 세대 누적 잔액을 별도로 표시하고 저장 후 두 상태를 함께 미리 보여준다.
- 이번 정산서보다 큰 입금은 다른 정산서 미납 반영과 실제 세대 초과납부를 구분해 안내한다.

## 1. 사용자 증상

이번 달 신규 정산서 금액에 대해 전액 입금을 등록했지만, 입금액이 이번 달 고지액보다 크게 입력되고 이번 달 정산서가 `초과납부`로 표시됐다.

대표 재현 조건은 다음과 같다.

| 항목 | 금액 |
|---|---:|
| 별도로 남아 있는 과거 정산서 미납 | 17,000원 |
| 이번 달 정산서 금액 | 8,000원 |
| 세대 전체 누적 미납 | 25,000원 |
| 사용자가 이번 달에 납부하려는 금액 | 8,000원 |

v1.0.4의 전액 입력은 이번 달 정산서 잔액 8,000원이 아니라 세대 전체 누적 미납 25,000원을 채웠다. 입금 기록은 이번 달 정산서에 연결되므로 해당 정산서는 17,000원 초과입금으로 표시됐다.

## 2. 확인된 근본 원인

v1.0.4에서 이월 포함 정산서 금액을 이월 제외 신규 요금과 비교하던 문제를 해결하면서, 모달의 전액 입력과 서버 판정 기준을 모두 세대 누적 잔액으로 통일했다. 이 변경은 정산서에 이월 미납이 포함된 경우에는 올바르지만, 과거 미납이 이번 정산서에 포함되지 않은 경우에도 전액 입력이 과거 미납을 자동 합산하는 부작용을 만들었다.

납부 화면에는 서로 다른 두 잔액이 필요하다.

1. **이번 정산서 잔액**: 이월을 포함한 `FinalInvoice.total_amount`에서 이 정산서에 연결된 입금만 뺀 금액
2. **세대 누적 잔액**: 이월 중복을 제외한 세대 전체 실제 청구액에서 세대 전체 입금을 뺀 금액

전액 입력과 개별 정산서 완납 표시는 첫 번째 값을 사용해야 하며, 실제 세대 초과납부 여부는 두 번째 값을 사용해야 한다. v1.0.4는 두 범위를 하나로 취급했다.

## 3. v1.0.5 조치

### 3.1 이번 정산서 잔액 계산

`balance.invoice_outstanding_before_payment()`를 추가했다.

```text
이번 정산서 잔액 = 이월 포함 정산서 납부 안내액 - 이 정산서에 연결된 입금액
```

입금 수정 시에는 교체할 기존 입금 한 건을 제외하고 잔액을 다시 계산한다. 이 값은 전액 입력, 정산서별 잔액과 완납·초과입금 표시의 기준이다.

### 3.2 세대 누적 잔액 유지

세대 누적 잔액의 기존 불변식은 유지한다.

```text
세대 누적 잔액 = 이월 제외 전체 실제 청구액 - 세대 전체 입금액
```

이 값은 세대 전체 미납·완납·초과납부와 이후 정산 차감액을 판단한다. 이월 항목을 누적 청구에 다시 더하지 않으므로 중복계상 방지 정책도 바뀌지 않는다.

### 3.3 입금 범위별 안내

입금액을 다음 세 범위로 구분한다.

| 입력 범위 | 처리 |
|---|---|
| 이번 정산서 잔액 이하 | 이번 정산서에 정상 입금, 전액이면 해당 정산서 완납 |
| 이번 정산서 잔액 초과·세대 누적 미납 이하 | 확인 후 같은 세대의 다른 정산서 미납에도 반영 |
| 세대 누적 미납 초과 | 확인 후 초과분을 세대 초과납부 잔액으로 보존하고 이후 정산에서 차감 |

정산서 금액과 같더라도 이미 다른 입금으로 세대 누적 잔액이 더 작아진 상태라면 실제 세대 초과납부가 발생하므로 초과납부 확인을 표시한다.

### 3.4 화면 표현

입금 모달은 다음 정보를 분리한다.

- 정산서 납부 안내액
- 이 정산서 기입금액
- 이번 정산서 잔액
- 세대 누적 잔액

버튼 문구는 `이번 정산서 잔액 입력`으로 변경했다. 입력 중 미리보기에도 `이번 정산서 완납·미납·초과입금`과 `세대 누적 완납·미납·초과납부`를 함께 표시한다.

정산 이력 카드의 `정산서 금액`은 이월 포함 납부 안내액을 표시한다. 이월이 있으면 `이월 제외 신규 요금`도 함께 표시해 세대 누적 잔액 계산과 정산서 표면 금액이 다른 이유를 확인할 수 있다.

## 4. 회귀 방지 근거

`tests/test_payment_management.py::test_current_invoice_full_payment_does_not_include_older_outstanding`가 실제 오류 조건을 고정한다.

1. 과거 정산서 미납 17,000원을 남긴다.
2. 이월이 포함되지 않은 이번 달 정산서 8,000원을 추가한다.
3. 세대 누적 잔액이 25,000원이더라도 이번 정산서 납부 안내액은 8,000원인지 확인한다.
4. 이번 정산서에 8,000원을 입금한다.
5. 추가 확인 없이 저장되고 이번 정산서가 완납으로 표시되는지 확인한다.
6. 과거 미납 17,000원은 세대 누적 잔액에 그대로 남는지 확인한다.

기존 이월 포함 회귀 테스트도 보강해 신규 요금 8,000원과 이월 미납 17,000원이 실제로 포함된 25,000원 정산서는 25,000원 입금 후 정산서와 세대 누적 잔액이 모두 완납이 되는지 확인한다.

`tests/test_frontend.py`는 전액 입력 기준, 두 잔액의 별도 계산, 이월 포함 정산서 금액과 신규 요금 표시 문구를 확인한다.

## 8. 데이터·호환성 영향과 검증 한계

- DB 스키마 변경이나 마이그레이션은 없다. 기존 정산서와 입금 데이터는 그대로 사용한다.
- 이번 정산서 잔액 표시가 이월 포함 납부 안내액 기준으로 교정되지만 세대 누적 잔액 계산식은 변경하지 않는다.
- 다른 세대의 미납에는 영향을 주지 않는다. 모든 추가 입금 처리는 같은 세대 범위에서만 이뤄진다.
- 자동 테스트는 Flask API의 실제 저장과 렌더링된 모달 스크립트 계약을 검증한다. 데스크톱 창에서 버튼을 실제 클릭하는 UI 종단 테스트는 포함하지 않는다.
- 패키지 스모크 테스트는 세 운영체제에서 백엔드 시작·핵심 화면·튜토리얼 데이터·안전 종료를 검사하지만 운영 데이터 사본을 사용한 입금 조작은 수행하지 않는다.
