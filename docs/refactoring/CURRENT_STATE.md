## 1. 현재 시스템

BillCalculator는 단일 관리자가 다세대 주택의 전기·수도·공동 공과금을 세대별로
배분하고, 정산서 발행·입금·잔액·이월을 관리하는 Flask + SQLite 애플리케이션이다.
소스에서는 로컬 웹앱으로 실행할 수 있고, 배포본은 Electron 안에 같은 Flask 도메인 코드와
SQLite를 묶은 Windows·macOS 독립형 앱이다.

핵심 흐름:

1. 빈 DB 첫 실행에서는 격리된 연습 앱의 실제 화면으로 24단계 사용 안내를 진행한다.
2. 층·세대 마스터와 할인·공실·거주 인원을 등록한다.
3. 전기·수도·공동 요금을 입력하고 저장 전 세대별 미리보기를 확인한다.
4. 서로 다른 정산월의 계산 결과도 하나의 정산서로 묶을 수 있다.
5. 정산서를 인쇄·배부하고 세대별 입금과 누적 잔액을 관리한다.
6. JSON 전체 백업을 내보내고, 파일 또는 자동 복원 지점에서 고정 묶음을 선택해 복원한다.

`SQLSchema.txt`는 역사적 참고자료이며 스키마 생성에 사용하지 않는다. 빈 DB와 기존 DB 모두
`flask db upgrade`로만 생성·갱신한다. `db.create_all()`로 마이그레이션을 우회하지 않는다.

SQLite 실행 정책:

- `foreign_keys=ON`
- `journal_mode=WAL`
- `synchronous=FULL`
- `busy_timeout=5000`
- 통화는 `Money`(INTEGER 원), 배분 중간값·계량값은 `ExactDecimal`(TEXT)

### 데스크톱 배포

- Windows x64 NSIS, macOS 13+ arm64/x64 DMG를 대상별 네이티브 GitHub Actions 러너에서 만든다.
- PyInstaller one-file 백엔드에 migrations·templates·static을 포함하며 시작 시 자동 upgrade·설정 시딩·20개 정합성 검사를 수행한다.
- Electron은 단일 인스턴스로 동작하고 임의 loopback 포트의 백엔드를 관리한다. Node integration은 끄고 context isolation·sandbox를 켠다.
- 사용자 DB는 Windows `%APPDATA%`, macOS `~/Library/Application Support` 아래 BillCalculator 데이터 폴더에 저장한다.
- DB revision 변경 전 자동 백업을 만들고, 앱 종료 시 백엔드와 튜토리얼 프로세스를 정상 종료한다.
- `v*` 태그는 Windows x64·macOS arm64·macOS x64 산출물과 `SHA256SUMS.txt`가 포함된 GitHub Release를 자동 생성한다.
- 코드 서명과 Apple 공증은 제품 결정에 따라 비활성화되어 있다. 최초 실행 OS 경고는 배포 문서에서 안내한다.

## 3. 보존할 핵심 도메인 규칙

- 최종 세대 청구액은 10원 단위로 올림한다.
- 전기·수도 할인은 고지 순액을 할인 전 금액으로 되돌려 배분한 후 적용한다.
- 할인 대상 세대가 없으면 할인을 버리지 않고 실제 정산 대상 전체에 균등 배분한다.
- 할인액이 세대의 배분 가능한 요금을 초과하면 해당 세대만 0원으로 제한하고 남은 할인은 타 세대에 재배분하지 않는다.
- 전기 할인과 TV 수신료 적용 순서는 설정값을 따르며 계산 당시 정책을 `ElectricBill`에 저장한다. TV 기본 분배 설정은 계산 화면의 초기 선택만 정하고 실제 선택값은 계산별로 저장한다.
- 사용량 또는 총 인원이 0이면 정산 대상 세대에 균등 배분하고 저장 전 경고한다.
- 수도 제외 세대도 0원 상세 행을 보존한다.
- 서로 다른 정산월을 하나의 정산서에 포함하는 것은 의도된 정상 흐름이다.
- 전기요금은 매월 층별로 계산하고, 수도요금은 건물 전체에 2개월 단위로 고지되는 흐름을 기준으로 한다.
- 정산 원본은 정산서 하나에서만 사용한다.
- 입금이 있는 정산서는 삭제하지 않는다.
- 이월 항목은 정산서 표시 총액에는 포함하지만 누적 잔액에서는 제외해 이중계상을 막는다.

## 4. 불변 스냅샷

계산 상세의 `unit_snapshot`은 아래 11개 키를 보존한다.

```
unit_id, floor_id, floor_number, floor_name, unit_name,
electric_welfare, electric_voucher, has_tv, water_welfare,
residents_count, is_vacant
```

계산 상세 화면은 현재 `Unit`/`Floor`가 아닌 이 스냅샷의 세대명·층명을 표시한다.
`0003_calculation_identity_snapshots`가 기존 SQLite 상세를 보강하고, v1 JSON 백업과 MySQL 이전
스크립트도 동일한 식별 스냅샷을 생성한다.

발행된 `FinalInvoice`는 세대명·층번호·층명·세대 비고를 별도 스냅샷으로 보존한다.

### 첫 실행 사용 안내 격리 정책

- 일반 실행의 새 업무 DB는 Alembic 스키마와 등록 설정 11개만 가지며 층·세대·계산·정산·입금 더미 데이터는 자동 생성하지 않는다. 데모 데이터 생성은 명시적인 데모 실행과 세션별 튜토리얼 DB로 제한한다.
- 업무 데이터가 없고 완료 상태가 아닐 때만 주요 화면에서 자동 안내한다.
- 기존 더미 생성기는 세션별 `tutorial_sessions/tutorial-<무작위 ID>.db`를 생성하고 `tutorial_runtime.py`가 로컬 전용 보조 프로세스로 실제 앱 화면을 제공한다. 운영 DB 연결은 바꾸지 않는다.
- 사용 안내를 열 때마다 이전 연습 프로세스를 종료하고 생성기 식별 정보가 유효한 해당 실행 DB를 삭제한 뒤, 새 무작위 실행 식별자와 최신 데모 데이터로 첫 단계부터 시작한다. 완료·종료·재시작도 해당 실행 DB와 보조 파일만 삭제한다. 미식별·심볼릭 링크·하드링크·현재 사용 중인 DB는 삭제하지 않는다.
- 완료 상태는 업무 DB와 같은 폴더의 `app_state.json`에 원자적으로 저장해 전체 JSON 복원의 영향을 받지 않는다.
- 기존 데이터가 있는 사용자는 자동 안내 대상이 아니지만 공통 메뉴의 `사용 안내`에서 언제든 재실행할 수 있다.
- 첫 단계는 공통 GNB의 `사용 안내`를 직접 강조하며 실제 GNB에도 `다시 보기` 배지를 유지한다. 이후 실제 설정·계산·상세·정산·납부 라우트의 요소를 직접 조작한다.
- 본 앱과 연습 앱은 포트가 달라도 충돌하지 않게 서로 다른 세션 쿠키를 사용한다. 완료·종료·재시작 요청은 24시간 제한 서명 토큰과 현재 본 앱 세션을 함께 검증한다. 단계·자유 연습 상태는 실행 식별자로 구분한 URL·호스트 쿠키·브라우저 저장소에 함께 기록해 포트 변경이나 저장소 접근 제한에도 복구하고, 이전 실행과는 이어지지 않는다.
- 튜토리얼 HTML은 일회성 보조 서버가 제공하되 CSS·JavaScript는 안정적인 본 앱 주소에서 불러온다. 패키징된 앱은 정적 자원 주소에 앱 버전을 붙여 Windows·macOS의 이전 캐시가 새 HTML과 섞이지 않게 하며, 릴리즈 빌드 스모크 테스트가 실제 보조 프로세스 실행과 자원 응답까지 확인한다.
- PyInstaller onefile 앱에서 데모 DB 생성기와 튜토리얼 서버를 띄울 때는 `PYINSTALLER_RESET_ENVIRONMENT=1`로 각각 독립 인스턴스를 만들고 `PYTHONIOENCODING=utf-8`로 입출력을 고정한다. 특히 Windows에서 부모의 임시 압축 해제 디렉터리 재사용이나 한국어 로그의 기본 코드페이지 변환 때문에 보조 작업이 조기 종료되는 문제를 방지한다. 서버 시작 실패 시 임시 출력의 마지막 부분을 오류에 포함해 릴리즈 검증에서 원인을 확인할 수 있다.
- 안내문은 데스크톱 오른쪽, 모바일 하단 패널에 고정한다. 배경 마스킹 없이 보라색 테두리 애니메이션과 흰색 말풍선으로 확인하거나 누를 실제 대상을 안내한다.
- 단계별 대상·필수 입력·열린 모달·안내 패널 외의 메뉴, 버튼, 값 변경과 폼 제출은 차단하고 현재 대상을 다시 강조해 경로 이탈을 막는다.
- 강조 대상은 스크롤, 창·시각 뷰포트 크기, DOM·대상 크기 변경 중에도 계속 추적한다. 숨겨진 모달은 제외하고 실제로 열린 모달에서는 강조를 모달 본문으로 옮긴 뒤 닫힐 때 원래 대상으로 복귀한다.
- 데모 검침값으로 전월·이번 검침의 차이와 사용량 비례 전기요금 배분을 설명하고, 독립된 계산 결과를 실제 청구주기에 맞춰 정산서로 묶는 개념을 별도 단계로 설명한다.
- 튜토리얼 전용 세션 DB에는 세 층의 9월 전기요금, 1층·2층의 10월 전기요금, 9~10월 사용분인 10월 수도요금을 미정산으로 준비한다. 사용자가 지하층 10월 전기요금을 계산한 뒤 월별 모든 층의 전기 6건과 수도 1건을 하나의 10월 정산서로 만들고 각 정산월이 보존되는 것을 확인한다.
- 계산 미리보기·저장, 정산 항목 확정·미리보기·생성, 납부 이력 조회는 각각 성공 이벤트가 확인되어야 다음 단계로 진행한다.
- 정산서 생성 뒤 튜토리얼 모드에서는 인쇄용 보기를 같은 탭으로 열어 세대별 페이지와 포함 고지월을 확인한다. 실제 인쇄·취소·생략 모두 정산서 복귀 단계로 이어지고 인쇄 매체에서는 튜토리얼 UI를 숨긴다. 일반 모드의 새 탭 인쇄는 유지한다.
- 모든 단계에서 다음 단계 CTA와 구분선·설명·간격으로 분리된 자유 연습 전환 영역을 제공한다. 확인 후 전환하면 단계 대상 강조, 경로 강제 이동, 메뉴·폼 조작 차단을 해제한다. 작은 상태 안내는 모든 화면과 인쇄 미리보기에 유지하되 실제 출력에서는 숨기며, 같은 연습 실행의 화면 이동·새로고침 뒤에도 상태를 보존한다. 임의 변경 뒤 중간 단계의 전제가 깨지지 않도록 `안내 처음부터`는 현재 실행을 폐기하고 새 데모 데이터의 첫 단계로 이동한다.
- `연습 종료`는 전용 프로세스와 실행 데이터·브라우저 진행 상태를 폐기한 뒤 본 앱 첫 화면으로 이동하는 인계 HTML을 반환한다. 302 응답을 보내기 전에 보조 프로세스가 종료되는 경쟁 조건을 피하고, 자동 이동이 제한되어도 수동 복귀 링크를 제공한다.
- 백업 파일과 자동 복원 지점은 실제 데이터와 혼동될 수 있으므로 튜토리얼 서버에서 내보내기·파일 복원·자동 복원 API를 모두 403으로 차단한다. 설정 화면은 기능 위치를 유지하되 관련 컨트롤을 비활성화하고 실제 데이터 복귀 후 이용하도록 안내한다. 튜토리얼 모드의 삭제·덮어쓰기는 영구 자동 백업 파일을 생성하지 않는다.

## 5. 백업과 복원 정책

내보내기 형식은 `billcalculator-full-backup` v1이며 16개 업무 테이블을 모두 포함한다.
복원은 아래 5개 고정 묶음만 제공한다.

| 범위 | 교체 | 유지 |
|---|---|---|
| `full` | 모든 업무 데이터 | 없음 |
| `property_history` | 주택 구성 + 계산·정산·입금 | 앱 설정 |
| `master` | 층·세대 | 계산·정산·입금, 설정 |
| `accounting` | 계산·정산·입금 | 층·세대, 설정 |
| `settings` | 등록된 설정 11개의 값 | 내부 설정, 나머지 모든 데이터 |

중요 정책:

- 행 단위 merge/upsert는 하지 않는다. **선택 묶음 전체를 교체**한다.
- 선택하지 않은 묶음은 현재 데이터를 목표 DB에 합성해 보존한다.
- `master`는 현재 이력이 참조하는 세대·층의 구조 식별자가 백업과 다르면 차단한다.
- `accounting`은 백업 이력이 참조하는 세대·층의 구조 식별자가 현재 마스터와 다르면 차단한다.
- 세대 구조 식별자는 `(id, floor_id, unit_name)`, 층은 `(id, floor_number, name)`이다.
- 현재 데이터가 있는데 선택 백업 묶음이 비어 있으면 고위험 경고를 표시한다.
- 미리보기 토큰은 10분 동안 범위, 백업 본문, 현재 DB 지문을 묶는다.
- 적용 직전 SQLite 자동 백업을 만들고, 완전한 목표 DB를 하나의 트랜잭션으로 적용한다.
- 적용 중 20개 정합성 검사 중 하나라도 실패하면 전체 롤백한다.

`data/migration_20261105/BillCalculator_full_backup_20261105.json`은 수정 없이 최신 목표 DB에 적재해
검증했다. 새 정책 설정 2개는 기본값으로 보강되고 기존 전기 계산에는
`COMBINED_FLOOR_ZERO` 서버 기본값이 적용된다. 원본 16개 테이블 333행에 신규 설정 2행을 보강한
335행을 적재했고 정합성 검사 20개가 모두 통과했다.
해당 `data/` 산출물은 운영 데이터이므로 Git에 커밋하지 않는다.

## 6. 마이그레이션 이력

| revision | 역할 |
|---|---|
| `0001` | SQLite 초기 16개 업무 테이블 스키마 |
| `0002` | 정산서 수신자 스냅샷, 정산 원본 1회 사용, 공동요금 요청 토큰 |
| `0003` | 기존 계산 스냅샷에 세대·층 식별자 보강 |
| `0004` | 전기 계산 당시 할인 초과·TV 수신료 처리 정책 저장 |

MySQL 이전 스크립트는 원본을 읽기 전용으로 열고, 임시 SQLite에 적재·검증한 뒤 대상을 교체한다.
소수 통화, 중복 키, 고아 참조, 알 수 없는 설정은 임의로 보정하지 않고 보고서로 차단한다.

## 8. 운영 명령

```bash
source .venv/bin/activate

flask db upgrade
flask seed-settings
flask check-db
flask backup-db
pytest -q

python scripts/migrate_mysql_to_sqlite.py --mysql-uri "..." --report-only
```

실행 전 `BILLCALC_DB_PATH`가 의도한 DB를 가리키는지 확인한다. 업그레이드 전에는 `flask backup-db`로
별도 백업을 생성한다. `data/`, `*.db`, `*.db-wal`, `*.db-shm`, 이전 보고서는 커밋하지 않는다.

## 9. 주의사항

- 복원 정책을 merge/upsert로 바꾸지 않는다. 선택 묶음 완전 교체가 현재 제품 정책이다.
- 서로 다른 정산월 혼합을 오류로 처리하지 않는다.
- 계산 상세에서 `detail.unit.unit_name` / `bill.floor_ref.name`으로 되돌아가지 않는다.
- 기존 토큰 미리보기를 우회한 복원 엔드포인트를 추가하지 않는다.
- 정합성 검증 전에 운영 데이터를 임의로 보정하지 않는다.
- 스키마를 바꿀 때는 모델·Alembic·MySQL 이전·JSON 백업 호환·테스트를 함께 갱신한다.
